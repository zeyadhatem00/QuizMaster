# QuizMaster

QuizMaster is a client-side trivia game with a neon arcade interface. Choose a category and difficulty, set the number of questions, and answer each question before the 15-second timer expires. Questions are loaded from the [Open Trivia DB API](https://opentdb.com/); scores and the local leaderboard stay in the browser.

## Features

- Player name, question count (1–50), category, and difficulty selection.
- Random questions or questions from General Knowledge, Computers, Sports, History, and Science.
- Easy, medium, and hard difficulty options.
- Four shuffled answers per question, with mouse and `1`–`4` keyboard selection.
- 15-second countdown with a warning state and time-up feedback.
- Correct, incorrect, results, and retry feedback with bundled sound effects.
- Results screen with score, accuracy percentage, and a browser-local leaderboard.
- Responsive layout, focus-visible answer states, and reduced-motion styling.

## How it works

The app is a static site: there is no application server, user account, database, or project-specific environment file. On **Start Game**, the browser requests questions from Open Trivia DB using the selected amount, category, and difficulty. The client renders each question, tracks the score and timer, and writes leaderboard entries to `localStorage` under `playerslist`.

The main source files are:

- [`index.html`](index.html) — page shell, setup form, audio elements, and module entry points.
- [`js/ui-controls.js`](js/ui-controls.js) — custom category/difficulty controls and question-count state.
- [`js/main.js`](js/main.js) — API request, question rendering, answer handling, timer, scoring, results, and leaderboard.
- [`CSS/style.css`](CSS/style.css) — arcade theme, responsive layout, states, and accessibility styles.
- `images/` and `sound/` — favicon and bundled feedback/countdown audio assets.
- [`.github/workflows/static.yml`](.github/workflows/static.yml) — GitHub Pages deployment workflow for pushes to `main`.

## Requirements

- A modern browser with JavaScript modules, `fetch`, `localStorage`, and audio support.
- Network access to Open Trivia DB and the external Font Awesome and Google Fonts resources referenced by the page.
- A local static-file server for development. There is no `package.json`, lockfile, or package manager configuration in this repository, and no dependencies need to be installed.

## Run locally

1. Clone the repository and enter its directory:

   ```bash
   git clone https://github.com/zeyadhatem00/QuizMaster.git
   cd QuizMaster
   ```

2. Start a static server from the repository root. Python 3 is sufficient:

   ```bash
   python3 -m http.server 8000
   ```

3. Open [http://localhost:8000](http://localhost:8000) in your browser.

Serving the files over HTTP is recommended because the app loads ES modules; opening `index.html` directly with `file://` can be restricted by browser security policies.

## Play

1. Enter a player name (optional), choose a category and difficulty, and enter a question count from 1 to 50.
2. Select **Start Game** and wait for the API response.
3. Choose an answer by clicking it or pressing its displayed number key. The game advances automatically after feedback.
4. When the quiz ends, review the score and accuracy. **Play Again** reloads the page for a new round.

## External services and browser data

- **Open Trivia DB:** `https://opentdb.com/api.php?amount=<amount>&category=<category>&difficulty=<difficulty>` supplies the questions. An empty category value requests a random category.
- **Font Awesome 6.5.1:** loaded from cdnjs for interface icons.
- **Google Fonts:** `Orbitron` and `Rajdhani` are imported by the stylesheet.
- **Local storage:** leaderboard entries are stored only in the current browser profile under `playerslist`. Clearing site data removes them; no data is sent to a QuizMaster backend.

No API key or environment variable is required by the current source. The quiz cannot load questions when the external API is unavailable or blocked, and audio or CDN-backed styling can be affected by browser/network policy.

## Development notes

This repository contains the working client plus several commented design-reference snippets in [`index.html`](index.html). The active question, results, loading, and error screens are generated by [`js/main.js`](js/main.js); the commented reference markup is not an additional route or feature. The included workflow uploads the repository contents to GitHub Pages when run for the `main` branch, but this README does not assume that a public Pages URL is currently configured.

There is no automated test suite or build step in the repository. After editing, serve the root directory locally and manually exercise setup, question loading, timer expiry, answer feedback, results, and retry behavior in a browser.
